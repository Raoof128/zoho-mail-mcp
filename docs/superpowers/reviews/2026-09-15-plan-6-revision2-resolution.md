## Fresh review and follow-up corrections

A fresh-context reviewer checked the revised contracts and identified three residuals: preparation still depended on final RunIdentity, exact precommitted arguments could not contain future handles, and the resource example used the old result property. These were verified and corrected.

The follow-up pass confirmed the identity split and dependency approach, then identified local component-ready sources and the literal handle destination as missing cases. Both now have explicit schema support. The run/enable transition-receipt rule now applies only to recovery-mode manifests. The checker covers preparation sources without invented future hashes, component-ready sources without invented provider operations, handle dependencies, refusal of recipient/token substitutions, and component identities with null closure roots.

Server-generated arguments use a precommitted dependency DAG. Resolution validates an earlier source response and publishes its digest before slot consumption. It cannot replace literals or change recipients. A copied directory or new UUID cannot reset a consumed authorization slot. These remain implementation obligations, not a claim that persistence already exists.
